# Keil 本地自动化设计

目标：在现有单片机工作区，让 Codex 用稳定命令发现 Keil、检查工程、编译 C51 固件、启动 µVision 软件仿真、读取断言和串口输出，并留下可复查的结果。

## 取舍

采用官方 `UV4 -b/-r/-d` 和 Debug Initialization File。相比屏幕点击，它能记录退出码和日志；UVSOCK/DDE 交互适合以后扩展，本轮不增加协议服务。使用已安装的 Python 标准库和 PowerShell 入口，不安装依赖、不改变系统 PATH。

## 工作范围

- `smoke8051`：独立 8051 工程，验证 CPU、Timer0 中断、标准 UART、GPIO 外部输入和断言。包含错误 LED 引脚的负向用例。
- `stc-native`：复用此前 STC8H 最小原生源码与资料中的头文件，编译 STC8H8K64U 固件。STC 专有硬件不作为通用模拟器验收项。
- `board-bsp`：复制原资料工程到本轮运行目录，再编译；准确报告评估版限制。
- 任意工作区内 `.uvproj/.uvprojx`：检查目标与源文件，并在副本中编译。外部源文件/绝对输出路径不能隐式写回。

每次操作新建唯一 `runs/<时间>-<命令>/`，源副本、生成工程、调试脚本、编译日志、HEX 与结果位于该目录。失败不能借用以前的产物或 PASS。原资料和已有 Wokwi/STM32 工程保留。

## 验收

退出码与新日志共同判定编译，退出码 1 仅在明确零错误时视为警告；有效 HEX 必须通过校验。仿真必须具备本轮随机 ID、开始/结束标记、完整断言集和串口标记；调试进程退出码单独不能证明通过。等待有上限，仅清理本流程创建的进程。串行运行 Keil，避免许可证/全局状态竞争。

软件仿真不连接串口、不烧录、不复位实物。本轮没有已确认的 STC8H 专用外设仿真模型，不能声称验证板上 USB、ADC、PWM、I2C/OLED 或 1T 精确时序。

Codex 上下文由工作区 `AGENTS.md` 入口引导读取本地 `skills/keil-local/SKILL.md`。当前 `.agents` 是只读路径，技能放入普通工作区目录；不修改全局设置。
