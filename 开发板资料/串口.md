### STC8H/STC32 开发板串口通信系统完整说明

本文件旨在提供开发板上所有串口相关功能的**完整、精确且无歧义**的技术说明，确保任何智能体或开发者都能基于此文档正确理解和使用该硬件平台。

------

#### 1. 开发板概述

本开发板基于 **STC8H8K64U-LQFP64** (兼容 **STC32G12K128-LQFP64**) 增强型8051单片机设计。它集成了丰富的外设，包括双USB接口、CH340N USB-TTL转换器、ESP8266 WiFi模块、蓝牙模块、独立按键等，并通过巧妙的引脚复用和切换机制，实现了多功能集成。

------

#### 2. 核心单片机串口资源 (STC8H8K64U)

单片机内部集成 **4个独立的UART** (UART1-UART4)，每个UART均可通过寄存器配置映射到不同的物理引脚组。

表格

| UART      | 主要接收引脚 (RXD) | 主要发送引脚 (TXD) | 其他可选引脚 |
| --------- | ------------------ | ------------------ | ------------ |
| **UART1** | P3.0               | P3.1               | -            |
| **UART2** | P1.0 / P3.6        | P1.1 / P3.7        | -            |
| **UART3** | P0.0 / P5.0        | P0.1 / P5.1        | -            |
| **UART4** | P0.2 / P5.2        | P0.3 / P5.3        | -            |

> **注意**: 开发板上的物理连接决定了哪些串口被实际使用以及如何使用。

------

#### 3. 串口1 (UART1) - 下载与调试主通道

这是开发板最核心的串口，用于程序下载、固件更新和主控调试。

- **物理引脚**: `P3.0` (RXD), `P3.1` (TXD)

- 硬件连接

  :

  - 单片机 `P3.1` (TXD) → **直接连接** → CH340N 的 `RXD` (Pin 6)
  - 单片机 `P3.0` (RXD) → **直接连接** → CH340N 的 `TXD` (Pin 5)

- 关键特性

  :

  - **无跳线帽**: 连接是**硬连线**的，无法通过跳线断开。这意味着 `P3.0` 和 `P3.1` 在绝大多数情况下被CH340N占用。
  - **自动下载**: CH340N的 `RTS#` 引脚通过二极管 `D1` 连接到MCU的 `RST` 引脚，实现一键自动下载，无需手动复位。
  - **电平兼容**: MCU工作在3.3V，CH340N工作在5V。MCU的3.3V TTL高电平足以被CH340N识别为逻辑'1'，而CH340N输出的5V TTL信号在MCU的5V耐受范围内，通信安全可靠。

##### 3.1 CH340N 芯片详解

- **型号**: **CH340N** (非CH340C)
- **功能**: USB转TTL串口桥接芯片。
- **时钟**: **内置晶振**，无需外部晶振，简化了电路设计。
- **供电**: 由USB的 `VBUS` (5V) 直接供电。
- **接口**: 通过6针接口 `J1` 连接到USB母座（USB1或USB2）。

##### 3.2 USB 接口

- **USB1 & USB2**: 开发板提供两个物理USB接口，功能完全相同，均连接到CH340N。用户可任选其一进行连接。
- **用途**: 供电、程序下载、串口调试、仿真。

------

#### 4. 串口2 (UART2) - 多功能复用通道

UART2是开发板上**资源冲突最集中**但也**功能最丰富**的串口，通过引脚 `P1.0` (RXD2) 和 `P1.1` (TXD2) 实现。

- **物理引脚**: `P1.0`, `P1.1`

- **复用设备**:

  1. ESP8266 WiFi 模块

     - `WIFI1.TXD` → `P1.0` (MCU RXD2)
     - `WIFI1.RXD` → `P1.1` (MCU TXD2)

  2. 蓝牙模块

     - `P3.TXD` → `P1.0` (MCU RXD2)
     - `P3.RXD` → `P1.1` (MCU TXD2)

  3. DS1302 实时时钟

      (3线协议，非标准UART)

     - `U4.I/O` → `P1.1`
     - `U4.SCLK` → `P1.0`

  4. AD 转换输入

     - 电位器 `ADJ1` 中心抽头 → `P1.0` (作为ADC输入)

- **冲突解决机制**:

  - **硬件上无隔离**: 所有设备都直接连接到 `P1.0/P1.1`。
  - **软件/固件管理**: 用户必须在固件中**明确选择一种功能**，并确保其他设备处于非工作状态（例如，不初始化DS1302时，其I/O引脚为高阻态）。这是一个典型的“多合一”设计，依赖于正确的软件配置。

------

#### 5. 独立按键与串口引脚冲突

开发板的4个独立按键 (`K0-K3`) 直接连接到 `P3.0-P3.3`，这与串口1 (`P3.0/P3.1`) 和红外接收 (`P3.2`) 产生了**直接的硬件冲突**。

- **按键连接**:

  - `K0` → `P3.0`
  - `K1` → `P3.1`
  - `K2` → `P3.2`
  - `K3` → `P3.3`

- **影响与解决方案**:

  - **根本性冲突**: 当CH340N工作时（即USB连接电脑），`P3.0/P3.1` 被驱动，此时按下 `K0/K1` 可能导致短路或通信错误。

  - 实践建议

    :

    - 在需要使用独立按键的项目中，应**避免同时使用CH340N进行主动通信**。
    - 按键检测应在通信空闲期进行，或采用中断方式，并在固件中做好状态管理。
    - 此设计主要适用于**学习和演示**场景，在对可靠性要求高的产品中应避免此类冲突。

------

#### 6. 其他串口 (UART3 & UART4)

- **UART3**: 引脚 `P0.0/P0.1` 或 `P5.0/P5.1` 在原理图中未连接到任何板载设备，已通过扩展排针引出，可供用户自由使用。
- **UART4**: 引脚 `P0.2/P0.3` 或 `P5.2/P5.3` 同样未连接板载设备，通过扩展排针引出。

> **使用方法**: 若需使用这些串口，用户需外接USB-TTL模块，并将模块的TXD/RXD分别连接到对应的MCU引脚，并在程序中正确初始化所选的UART及其引脚映射。

------

#### 7. 内置USB HID (替代方案)

除了通过CH340N进行串口通信，STC8H8K64U还支持**原生USB HID**功能。

- **物理引脚**: `P3.6` (USB D+), `P3.7` (USB D-)
- **接口**: 连接到 **USB2** 接口。
- **用途**: 可用于免驱的USB通信、键盘/鼠标模拟、直接ISP下载等。
- **优势**: 无需CH340N驱动，速度通常更快。
- **注意**: 使用此功能时，`P3.6/P3.7` 不能再用作普通IO或UART2。

------

#### 8. 总结：引脚使用优先级与建议

表格

| MCU 引脚       | 主要功能           | 冲突设备   | 使用建议                                       |
| -------------- | ------------------ | ---------- | ---------------------------------------------- |
| **P3.0, P3.1** | UART1 (CH340N)     | K0, K1     | **默认用于下载/调试**。避免在通信时使用K0/K1。 |
| **P1.0, P1.1** | UART2 (WiFi/蓝牙)  | DS1302, AD | **固件中只能启用一个功能**。                   |
| **P3.6, P3.7** | USB D+/D- 或 UART2 | -          | 二选一，不可同时使用。                         |
| **P0.x, P5.x** | UART3/4            | -          | 安全，可自由用于扩展。                         |
